## 0.29.0 (2026-11-25)

### 🩹 Fixes

- On Android, a `scroll-view` or `virtual-list` in a screen presented as a `formSheet` now scrolls back up on a fresh drag, and a `native-header` in one is no longer padded by the status bar's height. ([#1873](https://github.com/ng-native/ng-native/pull/1873), [#1649](https://github.com/ng-native/ng-native/issues/1649), [#1648](https://github.com/ng-native/ng-native/issues/1648))

  Both default per screen: nested scrolling is on in a form sheet, as it is beside a `refresh-control`, and `consumeTopInset` is off, since a sheet never reaches the status bar. A screen pushed in a stack inside the sheet gets the same defaults, and one presented over the sheet does not. Setting `[nestedScrollEnabled]` or `[consumeTopInset]` still wins. `IN_FORM_SHEET` from `@ng-native/device` says whether a screen is in a form sheet. iOS is unchanged.

- On Android, a `text-input` or `switch` already on screen now follows an in-place light or dark change: a field's selection colour, cursor and selection handles, and a switch's press ripple. ([#1874](https://github.com/ng-native/ng-native/pull/1874), [#1592](https://github.com/ng-native/ng-native/issues/1592), [#1593](https://github.com/ng-native/ng-native/issues/1593))

  Before, they kept the colours of the scheme they were created in until the screen was made again. A `cursorColor` or `selectionHandleColor` set on the field stays, and so does a `selectionColor` unless it is the old scheme's own selection colour, which then follows the scheme. A switch with `thumbColor` keeps the ripple React Native gives it, and one with a `backgroundColor` keeps that background's ripple. The cursor and handles follow on Android 10 and later only.

- A `<pressable [menu]>` now opens its menu on iOS, as a UIMenu from the element on a touch or a VoiceOver press, with checked items shown checked, instead of firing `(press)` with a warning. ([#1829](https://github.com/ng-native/ng-native/pull/1829), [#1818](https://github.com/ng-native/ng-native/issues/1818))

  It takes the `NgNativeMenus` module's new `setPressMenu(nativeID, entries)`, which a development build has and Expo Go does not; in Expo Go a press still fires `(press)`, with one warning in development. The module lays a clear `UIButton` over the element's view, which UIKit opens the menu from, and takes it away while the pressable is disabled or once `[menu]` shows no item. UIKit has no way to open a menu from code, so on iOS `open()` returns false, with one warning in development.

- Taking the `<native-tab>` in front out of a `<native-tabs-outlet>` at runtime, with an `@if` for example, now navigates to the first tab still in the bar, which comes in front with its page once its guards allow it, instead of leaving a blank screen. ([#1891](https://github.com/ng-native/ng-native/pull/1891))

  The router navigates to where that tab was left, and keeps a page presented over the bar. When a guard on that tab refuses, the router stays on the removed tab's url. A tab taken out while a screen pushed over the whole bar is in front is not handled yet. A tab added again comes back where it was left. On Android, with react-native-screens 4.30, the removed tab's item still stays in the bar, as the native side never receives the removal.

- A view the engine paints on native without a commit, one whose transform or opacity changes again and again, is left to one graph of React Native's animated module a prop. The painter lets the view go before a scroll drive or a scroll-driven animation that sets a prop it paints connects to it, as it already did for a native `@keyframes` animation, where both used to set its transform and the one native updated last was drawn. And a view a graph has moved before, such as a sticky row, has the change that hands it to the painter painted on native, where it used to be left to a commit, which iOS and Android do not apply to a prop a graph has set: a list row taken out of the pool of parked rows kept its parked transform, and was drawn off the screen, blank, at its place in the list. ([#1843](https://github.com/ng-native/ng-native/pull/1843))
- A scroll drive or a native animation connected to a view whose transform or opacity the engine has set on native since a graph last let it go now lets the graph that set them go first. It used to let it go after, and React Native's C++ animated module, which keeps one graph a view, then forgot the new one too, so a commit could change the view under it. ([#1888](https://github.com/ng-native/ng-native/pull/1888))
- On iOS and Android a `<native-button>` draws an icon's SVG markup, `[icon]="{ svg }"`, before its label in the label's colour, and on Android it draws a bitmap `drawable`, which it took and drew nothing for before. ([#1841](https://github.com/ng-native/ng-native/pull/1841), [#1805](https://github.com/ng-native/ng-native/issues/1805))

  iOS and Android draw the markup once as an image, through the renderer an SVG `<native-tab>` icon uses: `withSvgIcons(SvgImages)` in `provideNativeRouter`, or the new `SVG_ICON_RENDERER` token from `@ng-native/device` in an app without the router. Without one the button shows no icon and says so once in development, where before it said that only macOS and Linux draw an SVG icon. On iOS the UIButton draws the image as a template image a symbol's height in the title's font, tinted as a symbol is, and an SF Symbol given too wins. The iOS button is native code in `@ng-native/components`, so the image draws in a development build and not in Expo Go.

  On Android the button lays its icon, an 18-point `<image>` of the drawable or of the drawn markup, in a row before its label and tints it in the label's colour, black where none is set. The drawable is drawn through React Native's image view, so a PNG or WebP drawable draws and a vector drawable written in XML still draws nothing. A button with no icon is laid out as before.

- `<expo-map>` now takes the props and events `expo-maps` has on one platform only, and a Google marker's `icon`. ([#1877](https://github.com/ng-native/ng-native/pull/1877), [#1549](https://github.com/ng-native/ng-native/issues/1549))

  On iOS, `annotations` and `(annotationClick)`. On Android, `mapOptions`, `userLocation`, `contentPadding`, `(mapLoaded)`, `(mapLongClick)` and `(poiClick)`. A marker's or an annotation's `icon` takes an image as `expo-image`'s `useImage` returns it and is sent as its shared object's id, as `expo-maps`' own views send it. On macOS the desktop host draws no annotations.

- On macOS, enabled app-owned menu items can take Cmd-[ and Cmd-] from the standard View menu, whose Back and Forward commands remain clickable. ([#1869](https://github.com/ng-native/ng-native/pull/1869), [#1851](https://github.com/ng-native/ng-native/issues/1851))
- On macOS, a streamed `fetch` body now delivers each chunk whole as it arrives. Before, the desktop host could hold back the last one or two bytes of a chunk until more data arrived or the request completed, which could delay a Server-Sent Events or NDJSON record until the next one. ([#1865](https://github.com/ng-native/ng-native/pull/1865), [#1847](https://github.com/ng-native/ng-native/issues/1847))
- `screenshot()`, `toMatchScreenshot()`, `toHaveColorAt()` and `colorsAt()` now work in device tests on macOS: the desktop host has the `NgNativeTesting` module, which draws the app's window in process and asks for no screen recording permission. Where the module is missing, the error now says to update `@ng-native/desktop` on macOS, and that the Linux host does not have it yet, instead of telling you to rebuild a development build. ([#1866](https://github.com/ng-native/ng-native/pull/1866), [#1846](https://github.com/ng-native/ng-native/issues/1846))
- `inherit` set in an element's own style, `style="width: inherit"` or `[style.width]="'inherit'"`, is now the parent's value, for the properties a stylesheet takes `inherit` for, where native used to get the word itself. ([#1884](https://github.com/ng-native/ng-native/pull/1884), [#1879](https://github.com/ng-native/ng-native/issues/1879))

  These are the sizes, `color`, `background-color`, `opacity`, the font and text properties a stylesheet inherits, the corner radii, and a border's widths, colours and styles. Any other property set to `inherit`, `initial`, `unset` or `revert` is dropped with a warning in development, as a stylesheet drops it. `font-family` keeps the word as it did, and the `border` shorthand set to `inherit` is still dropped.

- `<expo-video>` and `<expo-live-photo>` now have the view functions of `expo-video`'s and `expo-live-photo`'s React refs. ([#1876](https://github.com/ng-native/ng-native/pull/1876), [#1548](https://github.com/ng-native/ng-native/issues/1548))

  On `<expo-video>`, `enterFullscreen()`, `exitFullscreen()` and `startPictureInPicture()` work on iOS and Android, and `stopPictureInPicture()` on iOS, where `expo-video` has it. Each does nothing on macOS. Picture in picture needs `allowsPictureInPicture` and the config plugin's `supportsPictureInPicture`, and on Android a device that supports it. On `<expo-live-photo>`, `startPlayback(style?)`, `full` unless set, and `stopPlayback()` work on iOS. Each returns a promise, and does nothing before the view is on screen.

- `<expo-blur-target>` and `<expo-blur [blurTarget]>` give `<expo-blur>` on Android the content it blurs, as `expo-blur`'s `BlurTargetView` and `blurTarget` do. ([#1878](https://github.com/ng-native/ng-native/pull/1878), [#1550](https://github.com/ng-native/ng-native/issues/1550))

  Register the target with `registerExpoViews('expo-blur-target')`. On Android it is `expo-blur`'s `ExpoBlurTargetView`, and the blur commits its view tag as `blurTargetId`, which blurs with a `blurMethod` other than `none`. On iOS and macOS the target is a plain view. An Expo view registration can now name no view for a platform, which commits a plain view there.

- On macOS and Linux, committing retained Fabric nodes after a window resize keeps the layout at the new dimensions. ([#1857](https://github.com/ng-native/ng-native/pull/1857), [#1854](https://github.com/ng-native/ng-native/issues/1854))

Each was a full build, and before this nothing removed them. ([#1861](https://github.com/ng-native/ng-native/pull/1861), [#1840](https://github.com/ng-native/ng-native/issues/1840))
- On macOS and Linux, a safe-area view inside another one now gets the right insets in its first commit, so a page with its own `<screen-safe-area-view>` under a macOS window's toolbar no longer draws one commit at twice the toolbar's height before settling. ([#1839](https://github.com/ng-native/ng-native/pull/1839), [#1803](https://github.com/ng-native/ng-native/issues/1803))

  A safe-area view's new insets reach the layout only in the commit after the one that tells it, so a view inside it was measured from where it was still mounted and was told the insets the outer view was about to take. Each view is now measured from where the insets of the safe-area views around it will put it, whether they apply them as a margin (`<screen-safe-area-view>`, the stack's own inset view, `<safe-area-view mode="margin">`) or as padding (`<safe-area-view>`). A `<safe-area-provider>` inside such a view hears the frame it will have, too.

- `ng-native-desktop run` shows the app by its `expo.name`, and by its icon unless that is an Icon Composer `.icon` folder, on macOS, as a packaged app does, rather than as `ngn-macos` with a generic icon, and says how long a first build from source takes when the folder it builds in has none yet and no earlier line has already said so. ([#1834](https://github.com/ng-native/ng-native/pull/1834), [#1789](https://github.com/ng-native/ng-native/issues/1789), [#1796](https://github.com/ng-native/ng-native/issues/1796))

  On macOS `run` starts the host from a thin `<expo.name>.app` in `.expo/ng-native-desktop/dev`, a copy of the host whose Info.plist names the app, gives its bundle identifier and carries the usage strings a packaged app has, so the menu bar, About, Hide and Quit, the Dock and the app switcher name the app, and the Dock and the app switcher show its icon (`ios.icon`, else `icon`; an Icon Composer `.icon` folder shows only once packaged). The icon reaches the host as `NGN_DESKTOP_ICON`, which a host from an earlier release ignores.

  Being a bundled app changes three things in a dev run on macOS: a permission is asked for in the app's name and needs its usage string, as in a packaged app; notifications are available, subject to the user granting authorization, where a bare host had them off; and preferences are kept in the bundle identifier's own defaults, so those set by earlier dev runs, kept under the app id in the host's shared defaults, are not read.

  On Linux the app and its main window take the app's name (a window opened with a title of its own keeps it), and the windows take its `icon` where the app sets one (`ios.icon` alone gives none), offered to GTK as the windows' default icon; GNOME on Wayland still shows the app id and a generic icon until the app is installed from a package, and a dev run of an app whose package of the same app id is installed can show that package's name and icon.

  The first-build note was judged by the React Native version's whole cache, which every app shares, so a new install, or another app with libraries of its own, built for minutes with no note. The build now prints it for the folder it builds in, before Hermes or the host compiles.

  A host crash under `vitest --project macos` still names its crash report: the macOS launcher looks for reports named for `ngn-macos` and for the app a dev run made in `.expo/ng-native-desktop/dev` of its `cwd`, and its `executable` option takes several names.

- On Linux a `<text-input>` sends no `(keyPress)` for an input method's composition, as on iOS and macOS, and Space and Return press the focused view, as on macOS. ([#1835](https://github.com/ng-native/ng-native/pull/1835), [#1797](https://github.com/ng-native/ng-native/issues/1797), [#1819](https://github.com/ng-native/ng-native/issues/1819))

  With an input method such as Japanese or Pinyin, the GTK host sent a `(keyPress)` for each keystroke of a composition, Return and the arrows included. It now sends none from a composition's first keystroke to its commit; outside one, a key that types a character sends its `(keyPress)` as its text goes in, still before the change, and a named key such as Backspace or an arrow sends its own as it is pressed. A read-only input sends none for a key that types a character.

  On Linux, Space and Return (and the keypad's Enter) press a focused view, so a focused `<pressable>` fires `(press)` and a `<pressable [menu]>` opens its menu from the keyboard. A window's default button takes Return first, and a key held down presses once, as on macOS.

  The shortcuts docs now say that on macOS and Linux a `shortcut` with no modifier takes its key from a focused text input.

- A `var()` fallback written below zero, on a property that takes nothing below zero, now unsets the property when it is used, as Chrome does, in `em` as in points. ([#1883](https://github.com/ng-native/ng-native/pull/1883))

  `width: var(--x, -1em)` was clamped to 0, as `calc(1em - 2em)` is; a math function's result is still clamped. A `padding` or `border-radius` fallback with one side below zero, `var(--x, 4px -1px)`, now unsets every side, where it kept the others. A `margin` keeps a side below zero, as before.

- A `background-size`, `background-position` or `background-repeat` set on an element now draws, a `background` set on an element takes a position, size, repeat and a colour beside its last gradient, `background: var()` puts a weaker rule's size, position and repeat back at their initial values, and on macOS `-webkit-font-smoothing` reaches text inputs and search fields and takes a token, `inherit`, `initial` and `unset`. ([#1831](https://github.com/ng-native/ng-native/pull/1831), [#1795](https://github.com/ng-native/ng-native/issues/1795), [#1816](https://github.com/ng-native/ng-native/issues/1816))

  A `background-size`, `background-position` or `background-repeat` in a `style` attribute or a `[style]` binding was committed under names native does not read, and now commits what the same declaration in a stylesheet does; a value with a token, a unit other than `px`, `rem` or a percentage, or a negative size is dropped with a warning in development. A `background` in a `style` attribute or a `[style]` binding now takes `linear-gradient(red, blue) center / cover no-repeat` and `linear-gradient(red, blue) green`, which were dropped with a warning. `background: var(--x)`, in a stylesheet or set on an element, used to leave a weaker rule's `background-size`, `background-position` and `background-repeat` in place; it now puts them back at their initial values, or, where the token is a layer with no image such as `center / cover`, places an image a stronger rule declares as the token says. On macOS, `-webkit-font-smoothing` now draws on a `<text-input>`, single-line and multiline, and a `<search-field>`, while they are edited too (but for a secure entry's dots), and `registerViewName` takes `fontSmoothing: true` for a view of a library's that draws it. `-webkit-font-smoothing: var(--x)` used to be dropped with a misleading vendor-prefix warning, and `inherit`, `initial` and `unset` with a warning; a token that is none of its keywords, or such a value set on an element, now leaves the inherited value, as in Chrome, where it used to draw as `auto`. On macOS, `font-family: Menlo` now draws in Menlo, where it drew in SF Mono, and a `<search-field>` draws `monospace` and `ui-monospace` in SF Mono, where it drew the system font; `<code>` on macOS, which the element styles give Menlo, now draws in Menlo as on iOS.

- Arithmetic on a token is now read for a property that takes a number, `flex-grow`, `opacity`, `order` or `z-index`, and for a `line-height`, where it used to be refused or unset. ([#1882](https://github.com/ng-native/ng-native/pull/1882))

  `opacity: calc(var(--o) / 2)` and `flex-grow: calc(var(--g) * 1.5)` were refused before, and `line-height: calc(var(--l) * 1.5)` with a number token was unset; each now comes out as in Chrome. A line height from a length token is a length, as before (`leading-6`), and so is `calc(var(--n) * 1px)` from a number token. A token of the wrong kind unsets the property, to `flex-grow`'s 0 for that one, as in Chrome. Tailwind's `-order-(--x)` and `-z-(--x)` now compile. `order` and `z-index` take a whole number, and Chrome rounds a fractional result for them; a fractional token's result is not rounded here yet.

- A `calc()` with a token in it that adds a number to a length is now invalid, as CSS finds it, in a token's own value and in a length, a number or a box shorthand that reads tokens; it used to commit as though the number were a length. ([#1881](https://github.com/ng-native/ng-native/pull/1881))

  A token holding one, `--t: calc(1px + 2)` in a stylesheet or set on an element, is read as no length and no number, so a `width: var(--t)` is unset, as in Chrome. Written in a declaration around a token, `width: calc(var(--t) + 2)` or a side of `padding`, it is invalid whatever the token holds, and is refused with a build warning, as a value of the wrong type written out is. A number that multiplies a token, `calc(-0.5 * var(--x))`, a length added to a percentage, a group in brackets, and a length divided by a length are read as before. A transform's arguments are not checked this way yet.

- `border: inherit` in a stylesheet now takes the parent's border, as Chrome does, and so do `border-width`, `border-color`, `border-style` and a side's width or colour. ([#1880](https://github.com/ng-native/ng-native/pull/1880))

  Each is the parent's value side by side, over what a weaker rule set, and a side the parent set as a logical one (`border-inline-start`) is the physical side it lands on in the parent's direction. Tailwind 3's `divide-inherit` now compiles. Still refused: a side's style (`border-top-style: inherit`) and a side's shorthand (`border-top: inherit`), since native has one border style for the whole box; a logical side (`border-inline-start: inherit`); and `inherit` written in an element's own style.

The pane is laid out at the card's size, so a page in it starts below the toolbar without a hard-coded top margin. iOS, Android and the web host ignore the input.
