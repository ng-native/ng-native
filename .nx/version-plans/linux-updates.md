Expo Updates works on the GTK desktop host on Linux, as on macOS: an app with an `updates.url` and a runtime version checks its own server with `expo-platform: linux`, downloads the update's launch asset and other assets, checks each against the manifest's SHA-256 and, with `updates.codeSigningCertificate`, the manifest's RSA SHA-256 signature, and runs the update after `reloadAsync` or at the next launch. An update whose launch crashes before 10 seconds on screen (or a clean quit) is not run again, and one whose kept manifest or launch asset no longer matches its signed manifest or hash is not run. Other kept assets are checked only for presence when the update launches. Updates are kept in `$XDG_DATA_HOME/<app id>/updates`. The hash and the signature go through the system's OpenSSL 3, which the host already links for TLS. The package manager or Flatpak still updates the app itself: `checkForAppUpdate()` stays inert on Linux.

On macOS and Linux, an update downloaded before the app itself was updated (by a package manager, Flatpak, Sparkle or a new copy of the app) no longer runs over the new version's embedded bundle, even with the same runtime version: the embedded bundle runs, and the old update's files are deleted, as are those of an update for another runtime version. The first launch of a host with this change runs the embedded bundle once, since the updates it finds were kept by an earlier host.
