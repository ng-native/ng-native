On the GTK desktop host on Linux, `audioPlayer()` and `audioRecorder()` work through GStreamer 1.22 or later, where its base and good plugins are installed.

A player plays a file or an HTTP or HTTPS source through PulseAudio's sink, which PipeWire also answers, keeping its pitch at any rate. A source with a stream no installed GStreamer plugin decodes fails with a message naming it; a stock RHEL 9 install has no H.264 decoder. A recorder records from the default source, through PulseAudio or PipeWire, as AAC in `.m4a` or `.mp4` (with an AAC encoder installed, such as bad-free's on RHEL 9), linear PCM in `.wav`, or Opus in `.ogg`; another extension is refused when the recording is prepared. Preparing a recording with no microphone present is refused, since PipeWire and PulseAudio record silence with no error when there is none; an output's monitor does not count as a microphone. Linux has no microphone permission, so the permission is always granted and nothing is asked; a Flatpak reaches the sound server, for playing and for recording, when the app has `expo-audio` or `expo-video` installed or declares `NSMicrophoneUsageDescription`. A recording that fails to finish writing its file reports the error in its `recordingStatusUpdate`. A host whose GStreamer has no source to record from still plays, and refuses to record. A host built without GStreamer, such as the dev loop on a Mac, leaves the module absent.

A `.deb` made by `ng-native-desktop package` depends on GStreamer 1.22 and its base, good and PulseAudio plugins, and suggests its bad plugins, which bring openh264 on Debian and Ubuntu, so a default install takes no H.264 decoder. An rpm requires GStreamer 1.22 with its base and good plugins and recommends bad-free, which has no H.264 decoder. Building the Linux host from source checks for GStreamer 1.22's development files.
