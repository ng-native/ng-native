A stylesheet's `:hover`, `:focus-within` and `:focus-visible` rules apply, where they were dropped with a build warning. `:hover` matches while a mouse, a trackpad or a pencil is over the element, never a finger, and only an element a `:hover` rule could match is told of the pointer, so an app with no such rule commits nothing more. On iOS and Android it takes the `pointerEvents` option of the `@ng-native/expo` config plugin, as `hovered` does. `:focus-within` matches the focused element and each element it is in. `:focus-visible` matches focus the host says came from the keyboard, which the macOS host reports; iOS and Android report none, so there it does not match. Media queries answer `hover`, `any-hover`, `pointer` and `any-pointer`: `hover` and `fine` on macOS, `none` and `coarse` on iOS and Android. `(pointerEnter)` and `(pointerLeave)` no longer run a second time for a pointer entering a view inside the one listening. On macOS, `fontScale` in the conditions and in `Accessibility` is 1.
