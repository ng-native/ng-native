macOS is reported as an OS of its own. The `OS` token from `@ng-native/device` is `'ios' | 'android' | 'macos' | 'web'`, where it used to read `'ios'` on every OS but Android and the web, and a new `DESKTOP` token is `true` on macOS, worked out from `OS`. `isApplePlatform()` from `@ng-native/fabric` is `true` on iOS and macOS. `registerPlatformComponents('macos')` draws with iOS's view names, except `<refresh-control>`, `<input-accessory-view>` and `<full-window-overlay>`, which are plain views on macOS. `@ng-native/tailwind`'s `native:` variant matches on macOS too, where it matched iOS and Android only. On macOS, `Dialogs.ask()` uses the iOS prompt, `<section-list>` pins its section headers by default, and `<markdown>` draws code in Menlo, as on iOS. A check an app wrote for iOS can now answer differently on a Mac: `=== 'ios'` is false there. And a check that already let a Mac through is worth a look: `!== 'android'` is true there, as it was, and `OS_VERSION`, the macOS major on a Mac, matches macOS 26 where a check meant iOS 26. The `os-comparisons-on-macos` migration notes the ones it recognises, with their file and line: a comparison of the OS with a quoted `'ios'` or `'android'`, and of `OS_VERSION` with a number, in code, templates and inline `template` strings. A check written another way, such as against a constant that holds `'ios'`, is not noted and needs checking by hand; see [Updating an app](https://ng-native.com/guide/updating) for how to run it.
